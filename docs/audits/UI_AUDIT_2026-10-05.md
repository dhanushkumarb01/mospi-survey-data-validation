# MoSPI V2 supervisor UI — internal audit before the final refinement

Date: 5 October 2026 · Scope: `fusion/ui/*`, `fusion/explain.py` (presentation layer), `fusion/api.py` (read endpoints). Inspected against the real V2 runs `fusion/runs/2024_first_visit_v2` and `2023_24_first_visit_v2`, served from a scratch copy so the real review audit files are untouched. Reference case: position 1 of 2024 (FSU 16125 · Household 02 · Person 02, Himachal Pradesh rural; self-employment earnings ₹1,85,000; typical ₹3,350 among 1,090 comparable records).

The scientific layers and the stored outputs are not in question here. Every number the current UI shows traces to a stored run. The problems are **hierarchy, repetition and load**.

## 1. Repeated information

The reference case states "₹1,85,000 is above the usual range" **seven times**:

1. headline ("brought to your attention because … above the range covering 9 in 10 …");
2. reason list (same sentence again, as a bullet);
3. "What looks unusual" tiles;
4. the statistical evidence card ("Observed" + "What it means");
5. the source summary table ("Statistical evidence … above the range …");
6. the right-rail "Case at a glance" figure;
7. the importance section.

There is more repetition:

- **Priority band and rank.** The band pill appears 3 times (header, rail, importance). The rank "1 of 1,66,722" appears twice.
- **"Unusual is not incorrect".** It appears in the caveat box, in each card's "Why it matters", and in the importance limitation.
- **The FSU disclaimer** ("FSU is not an enumerator") appears twice on the case page and twice on the Overview.
- **Step 4 duplicates step 3.** "What supports this flag" is a table that restates step 3 ("Why do we think it is unusual") card by card.

## 2. Unnecessary information on the primary path

- Stratum, visit, quarter, record key and case reference all sit in the header. They are useful for audit, but not for deciding.
- Every evidence card is open by default. Each one shows four boxes (Observed / Compared with / What it means / Why it matters) plus a facts table.
- "Identical answer sets in the same FSU" is shown as a full card even though it says "for information, does not affect priority". In the reference case it also says "0 matches".
- On the Overview:
  - a 5-band distribution with per-band progress;
  - a 10-State bar chart;
  - a long explainer about the 40% coverage;
  - two KPI rows.
  None of these answer "what should I review today?" first.

## 3. Overly technical language on supervisor screens

- Source labels such as "Statistical evidence", "Machine-learning evidence", "Contextual evidence" and "Pattern evidence (FSU level, context only)".
- "Strength: more unusual than about 99.9% of records assessed by this check". This is a percentile rank stated as prose.
- "Rank among records with a priority", "weighted total of its State/UT, sector and period", "Benjamini–Hochberg q-value" (Group alerts header), "robust standard deviations … simple-random-sampling standard error" (Area trends).
- "Occupation code 6" for the 1-digit occupation division. This is also inaccurate: it is an occupation *group*, not a code.

## 4. Missing hierarchy

- Seven numbered steps, all visually equal, with no single anchor saying what the record is and what is unusual about it.
- The decision area is step 7, below the importance section. On a 1366×768 screen it is about 5 screens down.
- FSU (group) evidence is a card in the same stack as record-level evidence. Its styling differs only slightly, so it competes visually with direct evidence.

## 5. Excessive cognitive load

- The reference case presents **6 evidence cards, a 5-row source table, 4 "unusual" tiles, a 3-item reason list, a checklist, a 3-row importance table and a JSON block**, all at once.
- At least 11 distinct numbers appear before the supervisor reaches the checklist.

## 6. Weak interaction

- Evidence cards are expandable, but all open at once, so expanding does not reveal progressively.
- There is no keyboard path to choose a decision.
- The Area trends chart is static: there is no hover, and no way to pick a change and see it.
- The Overview offers drill-down by band and State, but not by *reason*.

## 7. Weak visual storytelling

- The one meaningful chart (where the value sits) is in step 2, below the headline text. It is not the first thing seen.
- The trend chart and the case chart use the same blue as every other element, so colour carries no meaning.
- Colour is overused: red bars for State counts, blue for neutral bands, amber for medium.

## 8. Where it still looks like a generic dashboard

- Sidebar + KPI tiles + card grid + blue bars on the Overview.
- The "Records by priority" stacked bar and the "Where the highest-priority records are" bar chart.
- The Area trends page is a filter bar + chart + table + list, all at equal weight.

## 9. Real-data check

**No fabricated values were found.** All figures come from the API, which reads the stored Parquet and JSON outputs. Two representation issues need fixing:

- `/api/aggregates` returns only the 50 largest notable changes, while the Overview reports 51 area alerts. The list therefore silently drops one.
- The trend chart ignores which periods are missing. It is drawn from stored values only, which is fine, but sparse series should state that they are sparse.

## 10. Collapse, remove or move

| Item | Action |
|---|---|
| Reason list, "What looks unusual" tiles, source table, rail figure | **Merge** into one case summary (value, one-sentence reason, one comparison, one chart) |
| Evidence cards | **Collapse** to one compact row per source (finding + key fact); expand for comparison population, ranges and grouping; nested "Technical details" for ranks, scores and method |
| Identical answer sets | Move inside "Combination of answers" detail; show only if matches > 0 |
| FSU pattern card | **Move** to a separate violet "About this FSU — whole FSU, not this record" section after the checks |
| Importance (risk / influence / weight / rank) | **Collapse** to "Why this case is high on the review list" with two plain levels; numbers and limitation behind "How this was calculated" |
| Stratum, visit, quarter, record key, case reference | **Move** to a "Record details" disclosure; person facts stay visible beside the checks (needed for consistency checking) |
| Overview band chart, State chart, coverage explainer | **Replace** with queue → reasons → group alerts → area changes → progress; coverage explanation in one disclosure |
| Area trends method text | **Move** behind "How unusual changes are identified" |
| Technical reference | Keep everything; restyle as secondary |

Unchanged by design: calculation modules, stored runs, API contracts used by tests, the review audit trail, and the technical-detail JSON for each case.
